## 2. Where SKILL.md was ambiguous, wrong or missing a step

1. **“Survey 18–25 recent papers”** gives no rule for cutting a few hundred deduplicated records (here 510) down to 18–25. Every blind-spot count depends on that cut. *Would help:* an explicit inclusion rule (e.g. must evaluate on the target benchmark family; top-k by facet), or a required check of the gaps against the full pool. I improvised a regex count over the pool, and it showed that G3–G6 are thin, not empty.
2. **“Dimensions covered by ≤ 2 studies are blind spots G1..G7”** produced **zero** blind spots here. With 25 papers and 7 dimensions chosen to fit the topic, every dimension had ≥ 3. The skill says nothing for this case, and “G1..G7” suggests one gap per dimension. I improvised two extensions: the rule restricted to papers evaluated on repository repair (giving G1), and dimension pairs with ≤ 2 papers, ranked by shortfall against the count expected under independence (giving G2–G7). *Would help:* say whether gaps can be pairwise or conditional, and give a ranking rule. A fixed “≤ 2” also does not scale with N.
3. **“fill an N × 7 matrix with evidence for each filled cell”** does not say what counts as evidence (abstract, full text, a figure?) or how to record it. There is no full-text retrieval step; the bundled script only renders PDFs. I coded from abstracts and stored verbatim quotes, which a script checks. *Would help:* name the evidence source and require a quote or locator per cell.
4. **arXiv URL template** `search_query=all:<q>&sortBy=submittedDate`: multi-word `<q>` needs encoding and AND/phrase syntax (`all:a b` is not a phrase), and `sortBy=submittedDate` returns the newest papers, not the most relevant. I switched to relevance sort. The template gives no rate-limit guidance; arXiv returned HTTP 429 on 7 of 18 pass-1 queries and on every pass-2 query, even at 3–6 s spacing. *Would help:* a working query example, relevance sort, and a back-off note or a fallback (OpenAlex already carries arXiv-hosted records).
5. **OpenAlex template** leaves out that abstracts come as `abstract_inverted_index` and must be rebuilt, which the evidence step needs. It also does not say what “recent” means for `from_publication_date`.
6. **“Crossref, for venue upgrades”** misses ICLR/ICML/OpenReview venues, which are central for ML papers and have no Crossref DOIs. Title search with a year filter also missed some cases. The skill gives no similarity threshold for accepting a match. I used ≥ 0.95 and not `posted-content`, then fell back to WebSearch. *Would help:* name OpenReview/DBLP as the upgrade route for ML conferences and state the threshold.
7. **“Tag every remaining preprint as a preprint”** does not cover DOIs registered as Crossref `posted-content` by non-arXiv servers (here XSci, Research Square). I tagged them as preprints.
8. **“Each subagent returns structured records (ID, title, …)”** gives no schema or file format. I used deterministic scripts instead of subagents (the skill allows “parallel WebFetch calls”), which made the runs reproducible and kept the raw responses.
9. **Novelty check**: “drop or revise any blueprint that prior art already covers” gives no test for “covers”, no number of queries, and no rule on whether prior-art hits must be registry records. I ran 3 OpenAlex queries per blueprint, read the closest abstracts, and kept the hit IDs in `data/prior_art.json`.
10. **“Draft follow-up designs B1..B6”** does not say whether dropped designs should be replaced. I reported the 4 survivors and kept the 2 dropped ones visible.
11. **Impact-vs-compute chart** has no scale definitions. I defined 1–5 scales in the axis labels and stated that the placements are judgements.
12. **No report structure.** The skill names the PDF and `Radar.html` but gives no section list, page budget, or template, and no guidance on how figures are referenced from the HTML (relative paths worked). The `<Topic>` filename slot has no naming rule.
13. **“Also deliver the matrix CSV and the reference list with IDs”** gives no column format. My choices are documented in the deliverables table above.
14. **`pdf_tools.py render`** writes a `<pdf-stem>_preview/` directory next to the PDF. The skill does not mention it, so a user may be surprised by it or forget to inspect it.
15. **Selection bias is not addressed.** Nothing in the workflow checks whether a blind spot comes from the hand-picked set. In this run, CAPYBALA (W7225137459) and LingmaAgent (W4413267850) were in the pool but not retained, and both bear directly on G4–G6.

## 3. Not done or not verified

- **arXiv retrieval largely failed** (HTTP 429). Preprints that exist only on arXiv are under-sampled. How completely OpenAlex covers arXiv was not measured.
- **Full texts were not read.** All coding and metrics come from registry abstracts, so capabilities that are not in an abstract are coded 0, which biases counts downward (D5 and D7 most likely).
- **The SWE-agent paper** (agent-computer interfaces) was not returned by OpenAlex search, so it is absent. I did not add it from memory.
- **The retained set was chosen by one reader** without a second coder, so inter-rater agreement is unknown.
- **WebSearch venue upgrades** (four papers) rest on conference pages returned by search. I did not fetch those pages to check them.
- **The pool regex counts are a keyword heuristic.** I did not hand-check them for false positives or false negatives.
- **Metrics are quoted from abstracts.** None were re-derived.
- **No git commit was made, and nothing outside this directory was modified.**
