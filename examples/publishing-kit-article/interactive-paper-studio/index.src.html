The three models

1. Crop (fit=cover, centred). Display box DwxDh = 1000x420. Scale s = max(Dw/W, Dh/H). Source kept: Dw/s by Dh/s. Lost per side: (H - Dh/s)/2 vertically, (W - Dw/s)/2 horizontally. For 1376x768: s = 1000/1376, kept 1376 x 577.92, lost 95.04 top and bottom.

2. Feed card. Apparent size = type x card / W (the kit's legibility_report, which scales by cover width and ignores the crop). Legible when it reaches 10 px. In the article header it is type x s.

3. Hard wrap. Each paragraph-level block (paragraph, list item, quoted paragraph; headings, tables and code excluded) with n source lines shows n-1 <br> on dev.to. Re-wrap: greedy word wrap at C minus the 2-column prefix of - and > .

Assumption flagged: the proxy URL says gravity=auto; the evidence and the kit call it a centre crop. A saliency-based crop would move the cut lines; the 95/95 split holds only for a centred crop.
